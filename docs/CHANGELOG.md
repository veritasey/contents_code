## 10. 재료 메뉴 가로 스크롤 표시 바 추가 및 카테고리 하이라이트 버그 수정 (v8.1.2 → v8.1.3)

- **가로 스크롤 위치 표시 바**: 모바일 앱의 "재료 및 종류" 카드에서 6개 카테고리(소고기~곡류) 중 일부만 화면에 보이는 문제를 확인. 칩 목록 바로 아래에 얇은 바를 추가해, 전체 대비 지금 보이는 영역의 비중을 막대 너비로 표기하고 실제 스크롤 위치에 맞춰 막대가 함께 움직이도록 구현 (`updateCatScrollIndicator`). 스크롤이 더 있다는 걸 시각적으로 알 수 있습니다.
- **치명적 버그 수정 — 카테고리 재선택 시 이전 강조 표시가 지워지지 않던 문제**: `syncMobileUI()`가 모바일 카테고리 칩을 `[id^="m-cat-"]` 접두사로 찾고 있었는데, 이 패턴이 칩이 아닌 `m-cat-container`(칩들을 담는 컨테이너)에도 걸려서 매번 첫 반복에서 `null.classList` 에러가 나며 나머지 칩의 강조 해제 로직 전체가 조용히 중단되고 있었습니다. 그 결과 다른 재료로 바꿔 선택해도 이전 재료의 파란 강조가 지워지지 않고 계속 남아있었습니다 (이번에 새로 추가한 스크롤 바 요소도 우연히 같은 접두사라 같은 문제를 안고 있었음). 카테고리 칩에만 `m-cat-chip` 클래스를 붙이고 그 클래스로 찾도록 수정해 근본적으로 해결했습니다.

헤드리스 브라우저로 스크롤 바 위치 계산(합성 스크롤 값으로 검증), 카테고리 전환 시 하이라이트가 정확히 하나만 남는지, 그리고 기존 회귀 스위트(인터벌 누수, 돌발상황/골든타임, 개인화, 서비스 탭 전체)를 모두 재검증했으며 콘솔 에러 없이 통과했습니다.

## 9. 화면 스케일링 방식 조정 및 마이너 수정 3건 (v8.1.1 → v8.1.2)

- **전체 UI 스케일링 되돌림**: v8.1.1에서 도입한 "전체 화면을 1600×900 프레임으로 고정 후 축소/확대"하는 방식이 오히려 글자를 작게 만들어 가독성을 떨어뜨린다는 피드백을 반영, 기기 패널·코어 시스템 컬럼은 기존처럼 뷰포트에 반응하는 동적 레이아웃으로 되돌렸습니다.
- **모바일 목업 전용 스케일-투-핏**: 대신 오른쪽 모바일 목업(휴대폰)에만 자체 축소/확대 로직(`fitPhoneToColumn`)을 적용했습니다. 실제 폰처럼 360×780 비율을 유지한 채, 세로 공간이 부족하면 헤더·게이지·카드가 함께 비례해서 줄어듭니다. 조리 시작 버튼과 하단 탭(기기제어/서비스)은 폰 프레임의 하위 요소라 스케일과 함께 항상 화면에 남아 있고, 그래도 다 담기지 않는 카드 영역은 기존처럼 자체 스크롤됩니다.
  - 이 과정에서 그리드 행(row)이 뷰포트 높이에 맞춰 실제로 줄어들지 않고 콘텐츠 크기만큼 커지던 잠재적 레이아웃 버그(`min-h-0` 누락, `grid-template-rows` 미지정)도 함께 고쳤습니다.
- **모바일 드롭다운 폰트 통일**: `<select>`/`<option>` 요소가 브라우저 기본 시스템 폰트로 렌더링되던 것을 페이지 본문과 동일한 폰트(Segoe UI 계열)로 강제 통일
- **추천 시즈닝 믹스 라벨 변경**: 시즈닝 추천의 표시 라벨을 "육류 시즈닝" 같은 대표군 명칭에서, 기기제어에서 실제로 선택한 **부위**명(예: "채끝 추천 시즈닝")으로 변경. 추천 로직(대표군 4종 기반 매핑)은 그대로 유지됩니다.

## 8. 마이너 수정 8건 (v8.1.0 → v8.1.1)

- **화면 크기 자동 조절**: 전체 UI를 1600×900 기준 프레임으로 고정하고, 실제 화면 크기에 맞춰 자동으로 축소/확대(scale)되도록 변경. 어떤 창 크기에서도 3개 컬럼이 잘리지 않고 항상 다 보입니다.
- 모바일 앱에서 조리 완료 후 버튼 문구를 "확인 (초기화)" → **"조리 완료"**로 변경
- 모바일 앱 상단 노치를 아이폰형 알약 노치에서 **갤럭시 스타일 펀치홀 카메라**(작은 원)로 변경
- **실내 공기 환경 카드**: "(기준 대비 +30%)" 문구 삭제, 표시 수치를 미세먼지(PM2.5) 농도(㎍/㎥)로 변경하고 "기준: 15㎍/㎥ 이하 좋음" 기준선을 표기
- **후드/공기청정기/에어컨 버튼**: 앱 실행 시 무작위로 켜짐/꺼짐 상태를 정함(후드 70%, 공기청정기·에어컨 각 50% 확률로 켜짐). 켜진 기기는 파란색으로 표시하고, 버튼을 누르면 상태가 즉시 전환되며 하단에 "OOO 제품이 동작합니다." / "OOO 제품 동작이 종료합니다." 안내 표시
- **추천 시즈닝 믹스**: 기기제어에서 선택한 식재료 카테고리와 실시간 연동 확인 (기존에도 연동되어 있었음)
- **식후 웰니스 브리핑**: 조리 전에는 "오늘 권장 섭취 칼로리(2,000 kcal)"를 우선 표기, 조리 완료 후에는 이번 요리의 칼로리와 예상 소화 시간을 함께 표기하도록 변경
- **냉장고 재고 카드**: 재료를 선택하기 전 초기 화면에서는 유통기한이 임박한 조리 가능 재료 목록을 기본으로 표기하도록 변경 (선택 후에는 해당 재료로 전환)

모든 변경 사항은 헤드리스 브라우저로 검증했으며(화면 스케일 계산, 랜덤 기기 상태·토글 메시지, 카테고리 연동, 조리 전/후 카드 전환, 2회 연속 조리 사이클 인터벌 누수 없음, 돌발상황·개인화 흐름 회귀), 콘솔 에러 없이 통과했습니다.

## 7. 서비스 탭 (외부 연동 카드) 반영 및 정지 버그 수정 (v8.0.1 → v8.1.0)

### 서비스 탭 신설

모바일 앱 하단의 "서비스" 탭(기존엔 비활성 상태)을 실제로 동작하도록 구현했습니다. 기기 자체에 탑재되는 AI(개인화 학습·골든타임·돌발상황)와 달리, 외부 서비스(SmartThings/Samsung Food/Samsung Health) 3종은 진입점 카드 형태로 제공됩니다.

- **SmartThings — 실내 공기 환경**: 조리 전에는 "좋음(지수 24)", 조리 완료 후에는 "주의(지수 31, 기준 대비 +30%)"로 표시. 후드/공기청정기/에어컨 3개 실행 버튼 제공 (토글 방식, 실제 기기 제어 없이 상태 표시만)
- **Samsung Food — 추천 시즈닝 믹스**: 선택된 재료를 육류/채소/생선/곡류 4개 대표군에 매핑해 시즈닝 2종 추천
- **Samsung Health — 식후 웰니스 브리핑**: 조리 완료 후 재료별 예상 칼로리·소화 시간 표시, 밤 9시~새벽 4시 사이 완료 시 "야식 주의" 배지 추가
- **Samsung Food — 냉장고 재고**: 선택된 재료와 관련된 임의 재고·유통기한 예시 표시

카드 데이터는 모두 고정 매핑 테이블 기반이며 실제 외부 서비스 연동은 없습니다. "Samsung Food/Health에서 보기" 버튼은 로그에 기록만 남기는 데모 동작입니다.

### 치명적 버그 수정 — 조리가 영원히 완료되지 않던 문제

전 버전 전체에 걸쳐 존재하던 버그를 발견해 수정했습니다. `engineTick()`에서 조리 완료 시점(`virtualTime === totalSimTime`) 감지 로직이 `triggerPhase(5)`(완료 처리)를 호출한 뒤 `return` 없이 아래로 계속 진행되어, 같은 tick 안에서 "레스팅 단계" 조건(`virtualTime <= t4`, 이때 `t4 === totalSimTime`)에도 걸리면서 상태를 곧바로 `completed → resting`으로 되돌리고 있었습니다. `totalSimTime`이 정확히 `t4`와 같은 값이라 이 충돌은 매 조리마다 100% 재현됐습니다. 결과적으로 시뮬레이터는 항상 레스팅 단계에서 멈춘 채 절대 "조리 완료"에 도달하지 못했습니다 (인터벌 자체는 정상적으로 정지되어 화면이 얼어붙은 것처럼 보였습니다). `triggerPhase(5)` 호출 직후 `return`을 추가해 완료 처리와 단계 분기가 같은 tick에서 충돌하지 않도록 수정했습니다.

### 추가 수정 — 상태 간섭 정리

- 돌발상황(안전모드) 진입 시 골든타임 안내 배너도 함께 정리되도록 수정 (이전엔 두 알림이 서로 무관하게 겹쳐 있었음)
- 조리가 완료되면 사용자가 어느 탭(기기제어/서비스)에 있었든 자동으로 기기제어 탭으로 돌아와 개인화 피드백 카드를 놓치지 않도록 함
- 전체 초기화(`resetSimulation`) 시 서비스 탭의 후드/공기청정기/에어컨 토글 상태도 함께 초기화

### 검증 방법

헤드리스 브라우저로 다음을 자동 검증했습니다: 서비스 탭 4개 카드의 빈 상태/채워진 상태 전환, 조리 전·후 공기질 카드 값 변화, 서로 다른 재료 3종 연속 조리 사이클(인터벌 누적/속도 이상 없음 확인), 탭 20회 연타, 돌발상황 5회 연타 후 정상 복귀, 개인화 피드백 전체 흐름. 모두 콘솔 에러 없이 통과했습니다.

## 6. AI-enhanced experience 3종 반영 (v7.8.1 → v8.0.1)

`AI-enhanced experience(TBD)` 로드맵 슬라이드에서 우선순위로 선정한 3개 기능을 시뮬레이터에 반영했습니다. 실제 센서·클라우드 ML이 없는 데모 환경이라, 아래 항목은 모두 규칙 기반 로직으로 그 동작을 흉내낸 것이며 진짜 AI 모델이 아닙니다.

- **굽기/식감 개인화 학습 AI**: 조리가 끝나면 우측 모바일 앱(온도 게이지 카드 아래)에 "이번 굽기 어떠셨나요?" 피드백 카드가 뜹니다. 덜 익음/딱 좋음/더 익음 중 하나를 고르면 재료+부위+굽기 조합별로 목표 온도가 ±0.5°C(최대 ±3°C) 조정되어 브라우저에 저장되고, 다음에 같은 조합을 선택하면 "목표 굽기" 카드에 적용된 오프셋이 배지로 표시됩니다. 선택 즉시 "다음 조리부터 적용됩니다" 안내와 함께 팝업은 자동으로 사라집니다.
- **소스/버터 골든타임 알림**: 가열 조리 단계가 85% 진행되면 우측 모바일 앱 화면 상단에 One UI 푸시 알림 스타일의 팝업과 15초 카운트다운이 뜹니다. 재료 카테고리별로 안내 문구가 다릅니다 (예: 소고기 "버터를 올려 베이스팅하세요", 채소 "마무리 양념을 더해주세요").
- **돌발상황 실시간 AI 대처**: 중간 컬럼(HW Actuators 패널 하단)의 테스트 버튼을 누르면 과열 상황을 인위적으로 발생시킵니다. 히터 출력을 즉시 0%로 차단하고 후드를 완전 개방하며, 우측 모바일 앱에 안내 문구와 "안전 확인 후 재개"/"조리 중지" 버튼이 있는 팝업이 뜹니다. 동시에 좌측 기기 LCD 패널은 "⚠️ 안전모드 작동" 짧은 상태 문구로 바뀝니다.

- 시뮬레이션 반영: 측정된 고기의 두께 및 조리 특성에 따라 소요 시간 시뮬레이션 (예: Beef 스테이크 Tenderloin 25mm Medium-Rare 조리 시 약 20분 소요)
- Time Frame 스케일: 왼쪽 두께 입력창 하단에 x1, x5, x10, x20, x30 시간 스케일 선택 기능 추가 (조리 과정과 시간 동기화)

## 3. 동작 오류 수정 및 레스팅/가열 조건 반영 (260728 1010 ~ 1030)

- 동작 오류 수정: 좌측 입력창에서 조리 시작 시 가운데 창에서 정상 작동하도록 수정
- 조리 및 레스팅 로직: 좌측창의 예상 소요 시간만큼 가운데 창의 동작 소요 시간이 재료 온도를 감안하여 유사하게 소요되도록 반영. 조리 가열 시 재료 온도는 45도에서 중단하고 레스팅하여 57도까지 상승 후 종료
- 용어 변경: 시뮬레이터 내 "심부온도" 표현을 "재료온도"로 변경

## 5. 한국 기준 소비 순서 정렬 및 최종 v6.6 반영 (260728 1400 ~ 1450 v6.6)

각 항목별 한국 기준 선호/소비 순서에 따른 부위 정렬 적용:

- Grains: White Rice / Mixed Grains / Brown Rice / Corn / Etc. → 바로 조리
